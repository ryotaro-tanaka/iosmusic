# M1-1 仕様書: 曲一覧表示（ローカルM4Aの検出）

最終更新: 2026-02-28

## 1. 目的 / スコープ

- 特定フォルダ内の再生可能なM4Aファイルを検出し、一覧表示する。
- M1-1では「一覧表示の安定性」を最優先し、再生機能は扱わない。

## 2. 非スコープ

- 音声の再生/停止
- シーク操作
- バックグラウンド再生
- ロック画面連携

## 3. ユーザーストーリー

- ユーザーとして、端末内のM4Aファイルをアプリ上で一覧確認したい。
- ユーザーとして、ファイルが0件の場合に「見つからない」状態を認識したい。

## 4. 機能要件

### 4.1 ファイル探索

- 対象は「事前に定義した特定フォルダ」のみ。
- `.m4a` / `.M4A` を対象とする。
- 0バイトファイルは除外する。
- 壊れたファイルは「一覧対象外」とし、ログに記録する。

### 4.2 一覧表示

- 各行に最低限 `title`（ファイル名）を表示する。
- 内部で `id`（一意ID）と `uri`（再生用参照）を保持する。
- 並び順は「ファイル名昇順」に固定する。

### 4.3 状態表示

- 読み込み中表示を出す。
- 0件時の空状態メッセージを表示する。
- 読み込み失敗時のエラーメッセージを表示する。

## 5. 非機能要件

- 100件程度のM4Aで操作不能にならない。
- 連続3回の再読み込みで件数が一致する。

## 6. UI要件（最小）

- タイトル: 「曲一覧」
- ボタン: 「再読み込み」
- リスト項目: ファイル名
- 空状態: 「再生可能なM4Aファイルが見つかりません」

## 7. データ仕様

```ts
export type TrackListItem = {
  id: string;
  title: string;
  uri: string;
  durationMs?: number | null;
};
```

## 8. 例外・エラーハンドリング

- フォルダ未存在: 空一覧 + 警告ログ
- 読み取り失敗: エラー表示 + リトライ可能
- 不正ファイル: スキップしてログ記録

## 9. DoD（G1-1）

- M4A一覧取得と表示が安定する。
- 0件ケースと複数件ケースを確認済み。
- 手動確認中にクラッシュがない。

## 10. 検証手順（手動テスト）

1. 対象フォルダにM4Aを0件配置して起動し、空状態表示を確認
2. 対象フォルダにM4Aを3件配置して起動し、3件表示を確認
3. 「再読み込み」を3回実行し、件数が毎回一致することを確認
4. 0バイトM4Aを配置し、一覧に出ないことを確認

## 11. リスク / 未決事項

- iOS実機とシミュレータでファイル配置手順が異なる可能性
- フォルダ探索の実装方式（ネイティブ連携をどこまで行うか）

## 12. 次マイルストーンへの引き継ぎ（M1-2）

- M1-2では `TrackListItem.uri` を使って単曲再生を実装する。
- 一覧項目タップ時に `id` と `uri` を受け渡せるようにする。
