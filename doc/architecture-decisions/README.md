# 設計方針の事前意思決定（推奨）

MVP仕様とは別に、実装開始前に決めるべき設計方針をここに記録する。

## 目的

- 実装中の判断ブレを減らす
- M1からM4までの手戻りを減らす
- 役割分離とテスト観点を先に固定する

## 推奨ファイル構成

- `decision-log.md`: 意思決定一覧（要約）
- `decision-template.md`: 1件ごとの記録テンプレート

## 実装前に決めるべき主要項目

1. レイヤ責務（画面 / アプリケーション / インフラ）
2. 状態管理の境界（グローバル状態と画面ローカル状態）
3. ファイルアクセス方針（探索対象、エラー時挙動）
4. 再生制御APIの抽象（将来の差し替え可能性）
5. ログ方針（何をどこまで記録するか）
6. テスト戦略（どの層をユニット/結合/E2Eで担保するか）
7. Go/No-Go判定の運用（誰がいつ判定するか）

## 記録ルール

- 各決定は「背景 / 選択肢 / 採用理由 / 影響範囲」を必ず含める
- 決定変更時は「変更理由」を追記する
