# AD-006: テスト戦略（ユニット/結合/E2E）

- ID: AD-006
- タイトル: テスト戦略（ユニット/結合/E2E）
- 日付: 2026-02-28
- ステータス: accepted

## 背景

音楽アプリは再生・バックグラウンド・割り込み復帰など非同期イベントが多く、単一レイヤのテストだけでは品質を担保できない。M1〜M3 のゲートに沿ってテスト責務を分ける必要がある。

## 選択肢

1. ユニット中心（E2E 最小）
2. E2E 中心（ユニット最小）
3. テストピラミッド（ユニット + 結合 + E2E）

## 決定

テストピラミッドを採用し、各マイルストーンの DoD に紐づける。

- ユニット
  - キュー操作、再生状態遷移、探索フィルタ
- 結合
  - Store + UseCase + Repository/PlayerService
- E2E
  - 再生開始/停止/シーク
  - バックグラウンド 10分/30分継続
  - ロック画面操作
  - 割り込み復帰・再起動後復元

## 採用理由

- ロジック品質をユニットで高速に担保し、端末依存挙動を E2E で補完できる。
- ゲート付き進行（G1-1〜G3）と整合し、判定基準が明確になる。

## 影響範囲

- テストデータ/モック管理の方針が必要。
- CI に段階的な必須チェック（lint/typecheck/test）を組み込む必要がある。

## リスク / トレードオフ

- E2E の実行時間・保守コストが増える。
- 非決定的テスト（タイミング依存）の安定化が必要。

## 検証方法

- ユニット/結合/E2E の最小スイートを整備し、ゲート判定に利用する。
- 既知不具合を再現する回帰テストを追加し、再発防止を確認する。
